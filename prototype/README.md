# Макет интерфейса: мониторинг развития ребенка

Кликабельный статический макет: HTML, CSS и vanilla JS без сборки и без внешних CDN. Мобильный первый (ширина 360-420 px без горизонтального скролла), интерфейс на русском языке.

## Как открыть

- Двойной клик по `index.html` (работает через `file://`), либо
- из папки `prototype/`: `python3 -m http.server 8000` и открыть `http://localhost:8000`.

Данные хранятся в `localStorage` под ключом `child-monitor-prototype-v1`. Доступ к хранилищу обернут в try/catch, поэтому при недоступном хранилище макет работает в памяти. Чтобы сбросить демо-данные, удалите этот ключ в инструментах разработчика браузера.

Демо-аккаунты (пароль не проверяется, поле можно заполнить любым текстом):

| Роль | E-mail | Что видно |
|---|---|---|
| Родитель | `parent@example.com` | Два ребенка: Миша (доступ выдан двум специалистам) и Аня |
| Специалист | `specialist@example.com` | Только Миша, с одной своей заметкой |
| Специалист | `teacher@example.com` | Только Миша (без своих заметок) |

## Экраны и сценарии

| # | Экран (маршрут) | Сценарий | Эндпоинты API (контракт) |
|---|---|---|---|
| 1 | Вход и регистрация (`#/login`) | Переключение роли (родитель / специалист), вход, регистрация с полями e-mail, пароль (от 15 до 128 символов), полное имя и согласие на обработку персональных данных | `POST /api/v1/auth/login`, `POST /api/v1/auth/register`, `GET /api/v1/me` |
| 2 | Мои дети, родитель (`#/parent`) | Карточки детей с возрастом в годах и месяцах | `GET /api/v1/children` |
| 3 | Новый ребенок (`#/parent/new`) | ФИО, дата рождения, пол (обязательно) и срок рождения в неделях (необязательно, 22–44); подсказка «от 0 до 5 лет 11 месяцев»; ошибка, если возраст больше 5 лет 11 месяцев или дата в будущем | `POST /api/v1/children` |
| 4 | Профиль ребенка, родитель (`#/parent/child/{id}`) | Блок «Доступ специалистов»: список с e-mail, датой выдачи и кнопкой «Отозвать»; выдача доступа по e-mail. Блок «Заметки специалистов» только для чтения с автором и датой | `GET /api/v1/children/{childId}`, `POST /api/v1/children/{childId}/access-grants`, `GET /api/v1/children/{childId}/access-grants`, `DELETE /api/v1/children/{childId}/access-grants/{grantId}`, `GET /api/v1/children/{childId}/notes` |
| 5 | Мои дети, специалист (`#/specialist`) | Только дети с выданным доступом | `GET /api/v1/children` (для специалиста возвращаются выданные дети) |
| 6 | Страница ребенка, специалист (`#/specialist/child/{id}`) | Добавление заметки с счетчиком до 4000 символов; список заметок; «Редактировать» и «Удалить» только у своих заметок; без редактирования профиля и управления доступом | `GET /api/v1/children/{childId}`, `GET` и `POST /api/v1/children/{childId}/notes`, `PATCH` и `DELETE /api/v1/notes/{noteId}` |
| 7 | Блок «Показатели развития и динамика» (на страницах 4 и 6) | Заглушка. Логика блока (графики роста по стандартам ВОЗ, чек-листы вех CDC, сигналы, напоминания) уже работает в API и описана в `docs/00-monitoring-model.md`; макеты экранов — задача DIP-28 | `docs/07-architecture.md`, раздел 7.9; Swagger UI на `/docs` |

Ответ на запрос без доступа показан как «Ребенок не найден или у вас нет к нему доступа» (маршрут `#/specialist/child/{id}` для неизвестного или не выданного ребенка), что соответствует правилу контракта «нет доступа — 404».

## Что в макете не показано

- Редактирование и удаление профиля ребенка (`PATCH` и `DELETE /api/v1/children/{childId}`): в контракте есть, на экранах макета не выведено.
- Уведомления и история наблюдений (владелец Arsen, планируется).
- Health-эндпоинты, `/metrics`, `/docs` и `/api/v1/openapi.yaml`: это служебные страницы, не пользовательские экраны.

## Проверка

Сценарии (вход, валидация возраста, выдача и отзыв доступа, права на заметки, счетчик 4000 символов, отсутствие горизонтального скролла при 360 px) проверены headless-браузером. Синтаксис `app.js` проверен через `node --check`.
